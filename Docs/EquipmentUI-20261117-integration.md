# 八部位装备 UI 接入与联调入口

2026-11-17。对应 image 仓库 `designs/equipment-ui-20261117/README.md` 与 `ui/CONTROL-USAGE.md`。

## 当前入口

- 人物属性窗口的「装备」入口打开新装备总窗。
- 背包 → 工具 →「装备养成」也可打开；没有装备时仍能进入打造页。
- 总窗四页签：装备、打造、强化、法宝。Esc 先关闭当前弹窗，再关闭总窗；Tab/方向键使用原生 uGUI 焦点。
- 原背包、旧装备强化/镶嵌及旧资产仍保留。新装备详情中的空词条位可以安装，旧装备详情继续提供原强化/宝石入口。

## 真实接线范围

| 页面 | 已接入的行为 | 联调重点 |
|---|---|---|
| 装备总览 | 从同一个装备背包读取槽定义/占位；四基础装、双首饰、双法宝；人物摘要与单件属性分开 | 空槽、同名双实例、断线/换角色、权威面板同步 |
| 替换比较 | 从人物背包按指定槽准入类型筛实例；比较时锁定目标槽，提交前重查候选与原占用 | 首饰二/法宝二只替换第二槽；比较期间物品/槽变化不能错穿 |
| 定向打造 | 服务端配方目录、档位、权威预览、材料需要/持有/可用/缺少、资格及提交 | 材料不足、背包满、配置过期、连点、未决恢复 |
| 三池词条 | 按服务器显式位置及池选择；同件首饰重复禁选；确认原预览 | D11/E14/G11、空位、失效实例、逐条安装与再次打开 |
| 强化 | V1基础装列表、当前/下一级属性、费用、持有、必成/满级；调用既有强化状态 | 鞋速度不出现提升；首饰/法宝不列入；未决打造时禁写 |
| 法宝目录/详情 | 服务器八种配方，拥有/已装备按实例计数，再次兑换，单件条件/限次完整滚动 | 同名两件均计数；兑换与穿到指定槽分开确认 |
| 材料自选 | 服务端真实额度、打造/强化数量加减、等额确认、人物背包入账及原请求恢复 | 初始0/0、8+12或全选一种、满包、重复领取、跨日、断线重登 |
| 状态反馈 | 读取中、空列表、失败重试、互斥处理中、待确认结果；保留原请求恢复 | 关闭窗口不取消已发请求，不自动换键重新打造 |

美术的「本体+两条词条一次确认40材料」与现有协议不同：当前真实流程是先确认本体，再对每个空位分别预览、确认安装。页面明确显示这一步骤；不把三个独立事务包装成一次原子打造。首饰同理。示意图中的90/100级不写死进界面，实际只显示服务器配方档位。

同名双法宝按已实现业务规则各自生效、独立计次；详情始终展示服务器单件参数，不在UI另算战斗合计。美术文档中的旧“同名叠加待定”不覆盖最新玩法规则。

材料自选的协议缺口已补齐：PVE胜利与匹配PVP正常完成各产10份，两者共享每日20份上限；切磋、逃跑、作废及零回合不产出。每日按UTC+8的05:00重置已赚计数，未领取余额保留；不足20时领取实际批次，余额超过20时每批最多20。额度来自正式战斗结算，打开页面不会赠送材料。领取成功只有在服务端确认持久化后显示，未知结果与未持久确认保留原分配恢复。困难额外奖励与付费购买未加入。

领取revision只在成功领取后递增，战斗额度入账不改变它；原10份批次变20时服务端明确拒绝旧分配，可刷新后重选，不会卡在永久未知状态。已20份批次又获得10份时仍可正常领取本次20份。

## 自行打开与预览

1. 用 Unity 6000.6.0f1 打开 `D:\luyuan\mmorpg-client`；如果工程已打开，切回后等待资源导入和脚本编译完成，必要时使用 `Assets → Refresh`。
2. 联网测试打开 `Assets/Scenes/Bootstrap.unity`，启动配套服务后进入 Play，登录角色。点击人物属性窗口的「装备」，或「背包 → 工具 → 装备养成」。窗口与控件由代码创建，不需要另拖 prefab 或绑定按钮。
3. 先看「装备 / 打造 / 强化 / 法宝」四页签，再按下方清单验证真实请求与保存结果。
4. 如只想导出离线页面截图，退出 Play 后使用菜单 `MMORPG → UI → Capture equipment 20261117`。它手动创建并清理隔离预览场景，使用内存夹具，不联网、不修改账号资产，也不会自动运行。材料夹具包含0/0、8/12、未决和余额清零状态，计划导出15张截图。截图输出到 `.codex-artifacts/equipment-ui-20261117/screenshots/`，报告为同级上层的 `capture.result.json`。此菜单本轮未执行，不能把入口存在视为视觉验证通过。

## 联调顺序

1. 使用配套最新协议、配置和业务代码启动服务，登录后从人物「装备」或背包工具进入。
2. 材料足够时分别打造四类基础装、一件首饰和法宝，确认本体数量/消耗；逐个安装空词条并核对重登后保存。
3. 同模板打造第二件首饰/法宝，穿到第二槽；比较后替换，确认第一槽不变、背包与装备快照一致。
4. 强化查看服务端下一等级属性和费用；满级、鞋速度、首饰/法宝资格、材料不足逐项核对。
5. 提交期间断线/重连与关闭/重开窗口，检查“确认上次结果”恢复同一意图、没有重复产物。
6. 入战核对36词条、独立治疗/盾、双同名法宝的触发/限次/回放；UI不修改战斗公式。
7. 完成合格PVE或匹配PVP后打开「装备 → 材料自选」，两局合计最多20份。先分配8打造+12强化，验证背包增量；满包拒绝应保留额度。跨日检查待领余额保留，断线后点击「确认上次结果」不能再发一份奖励。需要更新后端程序后才能联调新增407/408接口，旧运行服务没有该功能。
