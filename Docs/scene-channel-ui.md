## 入口

- **角标**：主界面右侧入口列的顶上（设计坐标 2160, 72，330×80，与“地图”入口同款底图）。
  - 有目录且找得到所在线 → “N线 [L]”；有目录但找不到所在线 → “线路 [L]”；切线进行中 → “切换中…”（不带快捷键提示）。快捷键提示的写法与其它入口一致（“组队 [T]”“帮会 [G]”）。
  - 没有目录（副本 / 镜像 / 还没取到）→ 不显示角标。唯一的例外：自己发起的切线刚抵达、新场景的目录还没到的那一小段，先显示抵达的线号（它来自入场通知确认过的那次切线），目录一到就以目录为准。
  - 点击打开或关闭线路面板。
- **快捷键**：`L` 开关面板，`Esc` 关闭。正在输入文字、或别的模态窗开着时 `L` 不生效。
- **显示条件**：与其它主城入口一致——已进入游戏、连接就绪、战斗 / 观战画面不在屏上。不满足时入口隐藏、面板收起；在途的切线不受影响，结论仍由数据层给出。
- **互斥**：打开面板时收起帮会、组队、背包任务活动、地图、属性、宝宝、聚宝斋、仙笺、仙友会这些窗口。面板自带全屏遮罩和输入拦截，它开着时别的窗口的快捷键不会触发、别的入口点不到，所以没有去改其它窗口的代码。
- 画布排序 184（背包任务活动 180 之上、地图窗 185 之下）；角标所在的 HUD 子画布和其它入口一样是 140。

## 面板

设计面 2560×1080，居中纸面主框 1760×924，标题“选择线路”，副标题“当前：N线”（目录里找不到所在线时是“当前：未知”，没有目录时为空）。

- **线路区**：两列 × 八行，先左后右再换行；每页十六条，超过则分页（“上一页 / 下一页”，只有一页时整组隐藏）。从关着到打开时自动翻到所在线那一页；开着的时候目录刷新不会跳页。
- **每一行**是一个按钮：左边“N线”，右边色点 + 状态字。
  - 流畅（绿 `#3F9B4E`）、繁忙（橙 `#D98E1B`）、爆满（红 `#C23B22`），三色与选服界面一致；回收中 / 暂不可用 / 未知用灰色。
  - 所在线用选中态底图（深玉色），加“当前”标记，不可点但不置灰；它的状态字改用米白（绿字压在深玉底上看不清），颜色留给色点。
  - 只有“流畅 / 繁忙”且不是所在线的行可点；其余 `interactable = false`。
  - 切线进行中，目标行的状态字换成“切换中…”。
- **底栏**：状态行、翻页、“刷新”、“关闭”。
- **没有线路可列**时，线路区中央显示一句占位文字：“正在获取线路…” / “当前场景暂无线路信息。” / “线路信息尚未就绪，请稍候。”（未连接）。

控件命名（测试与截图按名字找）：行 `SceneChannelLine_{线号}`、刷新 `SceneChannelRefresh`、关闭 `SceneChannelClose`、翻页 `SceneChannelPreviousPage` / `SceneChannelNextPage`、角标 `SceneChannelEntry`。

### 整张面板置灰的情况

这些与点哪条线无关，每一行都不可点，状态行说明原因。判定用 `SceneChannelModels.EvaluateGlobal`，与数据层发请求前的校验是同一条规则。

| 情况 | 状态行 |
|---|---|
| 切线进行中 | 正在切换到 N线… |
| 战斗 / 观战中（排队匹配中也算，口径同地图窗） | 战斗或匹配中无法切线。 |
| 跨区传送在途 | 正在传送，请稍候。 |
| 在队伍里且不是队长 | 队伍中由队长切线，或先离队。 |
| 服务端关闭了切线 | 服务器暂未开放切线。 |
| 本地冷却未过 | 切线冷却中，N秒后可再次切线。（每帧刷新，向上取整） |

### 状态行的取舍

自上而下第一条命中（`SceneChannelWindow.DescribeStatus`）：

1. 切线在途 → 数据层的进度文字；
2. 上表里宿主或服务端此刻给出的原因（战斗 / 传送 / 队伍成员 / 服务端关闭 / 冷却）；
3. 数据层留着的失败提示（标红）：“切线失败，请稍后再试。”、“N线已满，请选择其他线路。”、“线路信息暂时获取不到。” 等；
4. 尚未就绪：列表空着时不重复说（占位文字已经说明），列表还在时给一句“线路信息尚未就绪，请稍候。”；
5. 数据层留着的其它文字（“已切换到 N线。”）；
6. 默认提示：“点击流畅或繁忙的线路即可切换。”，只有一条线时是“当前地图只有一条线路。”。

所有给玩家看的失败 / 置灰文案都出自数据层（`SceneChannelModels.DescribeBlock`、`SceneChannelClient` 的常量），界面只负责挑哪一句，不另写一套。

### 数据层留着的文字留多久

- **列线失败、本地拒绝的提示**（“线路信息暂时获取不到。”、“该线路已满…”、“操作太快了，请稍候再试。”）：下一次列线有了答复就收掉。
- **切线没成的结论**（“切线失败…”、“切线超时…”、“当前无法切线…”、“未能进入所选线路。” 等）：
  - 受理后被服务端提示判失败的那一种，失败时会顺手刷新目录；这第一份目录里那条线若已爆满 / 在回收，文案换成“N线已满 / 正在回收，请选择其他线路。”。之后每份目录都再核一次，那条线一恢复（或已不在目录里）就收掉。
  - 其余的：失败后的第一次列线答复先留着（失败时顺手拉的目录几十毫秒就到，立刻收掉等于没提示过），第二次起收掉。面板开着时大约留 2.5 ~ 10 秒。
  - 不这样做的话，面板每 5 秒刷新一次，“3线已满”的红字会和列表里已经恢复流畅的 3线 一直并排挂着。
- **切线进度与成功的结论**（“正在切换到 N线…”、“已切换到 N线。”）：留到下一次切线或进场。

## 行为约束

- **只发意图，等权威回包。** 点一行只是发出 `SwitchRequested(scene_id)`；所在线、线路列表只来自服务端目录和入场通知，界面不做本地假成功。点击时窗口按当前视图再核一遍，数据层发请求前还会再核一遍。
- **连点保护**：两次切线请求之间至少隔 1 秒，间隔内的点击由数据层本地拒绝并提示“操作太快了，请稍候再试。”。服务端的同步拒绝一个往返就回来，不拦的话连点第 4 下就会撞 gate 的限流（任意两个整秒内 3 次，切线与地图窗的同区换图共用一个消息号），每撞一次给会话记一次非法包，累计 50 次断线。真被限流（1008）之后退避 2.5 秒。断线重连后计时清零。
- **刷新节奏**：每次进场由数据层自动拉一次目录；面板打开时立即拉一次，之后每 5 秒一次（切线在途时不拉）；“刷新”按钮在列线尚无结论、切线在途、未连接时置灰。所有列线请求经数据层同一个出口，最小间隔 2.5 秒，太近的会排队到点补发。
- **刷新不重建行**：目录刷新时，只要当前页各行的内容（线号、状态、是否所在线、能不能点、是不是切线目标）没变，就只更新底栏，不销毁重建行按钮。否则每 5 秒两次的重建会吃掉恰好按在半途的点击（uGUI 要求按下和抬起落在同一个对象上），悬停高亮也会闪。
- **副本 / 镜像不列线**：入场通知（或列线回包里的当前场景信息）带着镜像 / 副本配置号时，数据层记为“这里没有分线”（`SceneChannelClient.DirectoryApplicable == false`）：进场不拉目录，之后谁来要也不发请求，面板显示“当前场景暂无线路信息。”。服务端对这类场景本来就只回不带目录的应答。
- **角标补问**：面板关着、而角标还显示不出线号（没有目录，或目录里找不到所在线）时补问：进场后第 15 秒、再过 30 秒、再过 60 秒各一次，**最多三次**，用完就停，等下次进场或玩家打开面板再拉；副本 / 镜像里一次也不问。进场那一刻目录恰好没发布（scene_manager 换主、Redis 抖动）或新线还没进目录的话，不补问角标会一直缺到下次换场景；不设上限的话，目录长期拿不到（目录发布被关掉、这张图没有线）时每个在线客户端都会无限期地每 15 秒发一条请求，还会让服务端的挂机判定（30 秒没有客户端消息）对站着不动的玩家永远不成立。
- **切线期间面板留在屏上当遮罩**：同图切线不重建地图，但入场通知会清空全部角色再由服务端重建。抵达后（只认入场通知里的 `scene_id` 等于目标）收起面板，并提示“已切换到 N线。”。玩家可以手动关掉面板；面板不在屏上时切线失败，会补一条提示。
- **同步应答之前到的入场通知不算这次切线的结果**：服务端是先写回同步应答、之后才可能为这次切线发入场通知的；应答还没到就收到别处的入场通知（队伍跟随、回收中的线被改派、更早的一次换图），只说明那条请求服务端还没处理。这时照常清目录、重新列线，但切线仍算在途，由随后的同步应答 / 入场通知 / 失败提示 / 等待期限收口。已受理之后到了别处才判“未能进入所选线路。”。
- **“结果未知”的失败，人到了要补结算**：服务端提示 1003（它不带请求号，别的模块路由失败时 gate 推的也是它）、同步应答超时、等待超时，这三种客户端都按“没成”收口，但服务端其实可能已经受理。此后 75 秒内目标线的入场通知到达，就按切线成功补结算：起本地冷却、状态行改成“已切换到 N线。”、收起面板。不补的话人过去了本地却不起冷却，紧接着再点只会吃到服务端的冷却拒绝（显示通用失败）。服务端明确拒绝的那些（同步拒绝、3023、3014）不记这一笔。
- **组队**：队伍成员（不是队长）整张面板置灰。队长可以切线，同节点的队员由服务端带过去。队伍状态读 `TeamUiRoot.Instance.State`；组队界面还没同步到队伍时按不在队伍处理。
- **断线 / 换连接 / 换 `GameClient` 实例**：数据层整体复位，面板收起，旧连接上迟到的回包不作数。
- 文字全部按纯文本渲染（不解析富文本标记）。

## 已知限制

- **同区换图在途时读不到。** 地图窗的同区换图请求状态是 `CityTravelUiRoot` 的私有成员，本界面只能读到跨区传送在途（`GameClient.IsTravelPending` / `IsRedirecting`）。实际上两者靠模态遮罩互斥：地图窗开着（换图期间它一直留在屏上）时角标点不到、`L` 不生效；服务端对“上一次换场景还没结束”也有同步拒绝（提示“正在切换场景，请稍候。”）。如果要做成显式互斥，需要地图窗公开一个只读的在途状态。
- **失败原因不细分。** 服务端把“满了 / 冷却中 / 回收中 / 功能关闭”统一折成一个失败码。客户端先显示“切线失败，请稍后再试。”，随后自动刷新目录；那条线若已爆满或在回收，文案会换成具体原因。冷却被拒（例如重登后本地倒计时丢了）只能看到通用文案。
- **冷却只在本地计时。** 服务端不下发剩余秒数；倒计时从自己发起的切线抵达那一刻按目录里的冷却秒数起算，重登后丢失。
- **角标不显示地图名**，也不显示各线人数；目录里有人数，面板目前只用状态字表达拥挤程度。
- **排队匹配中**与战斗 / 观战中是同一个置灰原因（与地图窗能否传送的口径一致），共用一句“战斗或匹配中无法切线。”，没有再细分。
- **“结果未知”的切线会先报失败。** 服务端提示 1003 时客户端立即按“切线失败”收口（不然要干等满 75 秒），这次切线若其实成了，玩家会先看到失败提示、随后被搬过去并看到“已切换到 N线。”。状态最终是对的（冷却照起），只是中间那句失败是误报。
- **角标补问只有三次。** 目录超过约 105 秒都拿不到时角标会一直缺着，直到下次进场或玩家按 `L` 打开面板（面板开着时每 5 秒刷新）。
- **窗口互斥是单向的**：本面板打开时会收起别的窗口，别的窗口的 `Toggle` 里没有加上本面板。靠遮罩和输入拦截，正常操作下打不开第二个窗口；用代码直接调别的窗口的 `Toggle` 则可能叠在一起。
- **角标在换图后会短暂消失**：进场即清空旧目录，新目录到达前没有目录，角标按规则隐藏（通常只是一次请求往返的时间）。自己切线抵达的情况不受影响，见上文“入口”的例外。
- 输入拦截依赖组件的启用 / 停用回调，EditMode 测试里不生效；面板打开时不能点地寻路这一点目前没有 PlayMode 用例覆盖。
