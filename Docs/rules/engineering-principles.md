# 工程设计与编码原则（Unity 客户端）

> 对应根索引 [AGENTS.md 开发分支与通用工程原则](../../AGENTS.md#开发分支与通用工程原则)，移植自服务端仓 `AGENTS.md §11`（`docs/rules/engineering-principles.md`）并适配 Unity C# 客户端与小游戏运行环境。适用于新增、修改、重构和代码评审。

原则冲突时按以下顺序取舍：

`正确性 / 安全 / 客户端与服务端状态一致性 / 向后兼容 > 简单 / 可读 / 与仓库一致 > 可维护 / 可测试 > 有数据支撑的性能（帧率 / 内存 / GC） > 假想扩展`

已锁定的 UI 原图零差异标准、WebGL 单线程/无阻塞红线、每帧热路径零无谓 GC 分配属于正确性约束，不降级为普通偏好。偏离本文件原则必须有明确需求或证据支撑，并在注释（如 `shortcut: <限制>, <何时升级>`）、文档或交付说明中记录原因。

## 1. 模块与职责（SOLID 与深模块）

- **单一职责（SRP）**：一个类只对一种变化原因负责。客户端严格区分三层职责：
  1. **通信与状态协调层**（`Assets/Scripts/Net/`、`Assets/Scripts/Game/**/*Client.cs`）：负责收发 RPC、认领回包、幂等重发、限流熔断衔接与权威状态缓存，不直接操作 uGUI 控件或场景 GameObject；
  2. **纯 C# 领域 / 视图模型层**（`*Model.cs`、纯逻辑状态机，**不依赖 `UnityEngine` 生命周期**）：承载状态推导、背包/装备可用量计算、按钮可点判定与文案组装，可直接被高速无头测试验证；
  3. **表现与交互层**（`Assets/Scripts/UI/`、`Assets/Scripts/World/` 下的 `MonoBehaviour`）：只负责把模型渲染到 uGUI / 场景并把玩家输入转交协调层，不在 UI 脚本里散落协议拼装与业务规则。
- **高内聚、低耦合与信息隐藏**：相关状态与行为就近收口，依赖单向不成环（`UI/World -> Game -> Net/Table/Proto`，底层绝不反向引用 UI）。用窄接口（如 `IRpcChannel`、`IBattleChannel`、`IFramedConnection`）隐藏传输、重连与平台差异；避免无隔离价值的连续透传包装或全能 `Manager`。
- **开闭（OCP）/ 里氏替换（LSP）/ 接口隔离（ISP）/ 依赖倒置（DIP）**：面对已确认的多变体（如原生 TCP vs 小游戏 WebSocket、真实网络 vs 测试假传输）在接缝处注入接口实现；替换实现不得改变回调次数（如 `CallMethod` 恰好回调一次）或错误语义。
- **组合优于继承**：优先用纯 C# 组件组合构建能力；**严禁在 Unity 中设计深层 `MonoBehaviour` 继承树**。

## 2. 简单、标准、可读（KISS / YAGNI / DRY）

- **KISS & YAGNI**：未上线阶段不堆砌历史兼容包袱，不写没有调用者或验收标准的预留配置、扩展钩子和死代码；发现已知问题或设计缺陷当场修复。
- **DRY**：一条业务规则在客户端只有一个真相点（例如幂等键生成统一走 `ClientRequestKeys`，限流与熔断统一挂 `GuardedRpcChannel` / `RpcGuard`，不各面板重复造轮子）；同时不为两三行偶合代码过早抽象。
- **直线控制流**：优先卫语句早返回，减少深层回调嵌套；注释只写代码本身无法表达的“为什么、服务端契约依据与边界风险”。
- **显式依赖，克制静态可变状态**：通过构造函数或装配入口（`GameClient` / `AppBootstrap`）显式注入依赖、时钟与通道；禁止新增隐式全局可变单例（会导致重连、换角、切服或 EditMode 连续跑测时残留脏状态）。
- **克制条件编译（对应服务端“非必要不写宏”）**：`#if` 会让非当前平台的分支脱离编辑器常规编译检查。除平台隔离硬边界（如 `#if UNITY_WEBGL && !UNITY_EDITOR` 小游戏桥、`#if UNITY_EDITOR || DEVELOPMENT_BUILD` 本地调试入口）外，不在业务代码里到处穿插条件编译。枚举显式关注真实取值域，用导表/协议生成的强类型枚举代替魔法数字。

## 3. 正确性、权威一致性与生产质量

- **服务端权威原则**：资产、属性、冷却、掉落、物理碰撞与胜负结算一律以服务端回包/推送为准；客户端本地预判或置灰仅作交互体验与防误触（如 `EquipBagModel` 可交易数、`CanSend` 限流置灰），不得拿本地计算或物理结果当作最终裁决。
- **边界防御与查表判空**：对服务端回包缺省字段、未知枚举值、`*TableManager.Instance.FindById(id) == null`（如旧存档遇删表行或热更时间差）必须显式安全兜底，严禁抛出未捕获 `NullReferenceException` 卡死登录、主界面或结算流。
- **请求结局三分法与幂等恢复**：严格区分**成功**、**确定未执行**（本地 `NotSent`、`circuit open`、`1008` 限流、转发前拒绝信封）与**结果未知**（超时、`1003`、断线）。只有“结果未知”且带幂等键的操作按规则原样重发或保留待确认记录；“确定未执行”绝不盲目重发，也不得误锁死面板（`RequiresReconnect`）。
- **单调时钟与 WebGL 单线程纪律**：网络超时、心跳、退避冷却一律按不受 `Time.timeScale` 影响的单调时钟推进，退避必须带上限与抖动；**严禁**在任何小游戏可达路径使用 `Task.Run`、`Task.Delay`、`Thread.Sleep`、`.Wait()`、`.Result`、线程池或异步文件/Socket API（完整清单见 [minigame-and-app-platforms.md](minigame-and-app-platforms.md)）。
- **敏感信息与帧热路径**：Refresh Token、签名密钥等敏感凭据严禁明文写入 `PlayerPrefs`、Git 仓库或日志；`Update` / `LateUpdate` / `Poll` / 高频消息解析热路径避免每帧闭包、LINQ、装箱与字符串拼接带来的 GC 尖峰。

## 4. 实例与布局分层（数据层 / 显示层，强制）

移植自服务端 `AGENTS.md §11.6`（完整设计见服务端仓 `docs/design/bag-instance-layout-split.md`）。一条结构只回答一个问题：**「它是什么」**，还是**「它摆在哪」**。适用于背包/仓库/临时格、装备穿戴、宠物出战、队伍站位、技能快捷栏、好友分组、邮件附件等系统：

- **实例层只描述实体本身**：`guid`、`config_id`、数量、强化/词条状态、时间戳；不把槽位号、格子坐标、排序序号硬绑成实体固有属性。
- **布局层只描述排列策略**：容量、槽位、格子占位、筛选排序。客户端布局推导不得反向污染底层实体结构，通用方法命名不泄漏特定布局（如区分“堆叠数”与“格子数”）。
- **「是什么」不与「在哪」混用字段**：装备实例上是种类（`equip_kind`），具体穿戴槽位由 `EquipSlot` 配置表枚举（支持同部位多槽，如双戒指/双饰品）；出战/佩戴关系按槽位表或显式映射读取，不写死“全身只能有一个某部位/一个出战位”的标量假设。
- **集合顺序必须显式**：绝不依赖 proto `repeated` 列表的数组下标充当业务槽位号或固定顺序，必须按显式 `slot` / `pos` / `result_seq` / 时间戳字段定位与排序。
- **纯 UI 临时态不混入权威数据模型**：选中态、展开态、闪烁动画计时、本地筛选关键词属于视图层状态，必须与服务端同步下来的权威快照分离，重拉全量快照时不得把协议对象当作 UI 状态容器覆盖丢失。

## 5. 连接、事件订阅与异步回调生命周期（强制）

对应服务端 muduo「只存 `weak_ptr`、只绑 `weak_ptr`」的崩溃复盘教训，在 Unity C# 客户端表现为**连接所有权混乱、事件泄漏、`MissingReferenceException`（异步回调命中已销毁 `UnityEngine.Object`）以及跨连接/跨角色串包**：

1. **连接所有权唯一**：大厅连接只归 `GameClient` 管理，战斗直连只归 `BattleDirectLink` 管理；业务 `*Client` 与 UI 面板**只注入窄接口（`IRpcChannel` / `IBattleChannel`）使用，绝不私自持有底层连接实例或越权开关连接**。
2. **订阅必有对称退订**：`MonoBehaviour` / 窗口 / 子面板在 `OnEnable` 或 `Awake` / `Bind` 中订阅 `GameClient` / `*Client` 的 C# `event` 后，**必须在 `OnDisable` 或 `OnDestroy` / `Dispose` 中精确 `-=` 退订**。否则 UI 销毁后仍被长生命周期 `*Client` 委托链强引用钉死在内存中，下次收到推送即在死对象上触发异常。
3. **异步回调先验世代与存活（客户端的“`lock()` 判空”）**：
   - RPC 回调、HTTP 回调、延迟刷新回来时，若目标是 `MonoBehaviour` / 控件，**第一步先判 `this == null || !isActiveAndEnabled`（Unity 重载判空）**，已销毁立即返回；
   - 若回调会改写角色/会话业务状态，**第一步先核对发起请求时的 `(PlayerId, 连接身份 / SessionEpoch)` 与当前是否一致**（断线、切服、换角、进场代次变化后到达的旧回包一律丢弃，绝不写进新角色或新连接状态）。
4. **换连接 / 换角一处清零**：在途调用、限流窗口、临时态和绑定本连接的锁状态必须在连接切换或角色登出入口确定性清理，不靠定时器“大概能跑完”兜底。

## 6. 测试与完成门禁

- **面向接口与纯模型单测**：新增或修复非平凡逻辑（状态机、重试幂等、限流熔断、布局换算、协议兼容桥接、UI 状态推导）必须配套可确定性复现的单元测试（注入假 `IRpcChannel` / 假时钟，不依赖真实外网、不依赖执行顺序或真实等待秒数）。
- **全链路调用点排查**：修改任何公共方法、协议字段或状态枚举前，先全仓搜索所有调用者、UI 绑定点、重连/换角清理路径与 `Assets/Tests/` 测试夹具，一次改全，不留半截改动导致测试程序集编译失败触发 Unity Safe Mode。
