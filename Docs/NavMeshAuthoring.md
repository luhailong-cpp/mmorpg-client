# 图片地图的 NavMesh 编辑

Unity 6000.6.0f1 菜单：**MMORPG → Maps → NavMesh 导航编辑器**。

此工具为后续新地图描绘地面与障碍，使用 Unity 官方 `NavMeshBuilder` 烘焙 `NavMeshData`，使用 `NavMeshAgent` 进行离线试走。官方 AI Navigation 2.0.16 也已加入项目；`Window → AI → Navigation` 可查看角色类型与区域设置。图片里的房屋和河流需要人工标注，烘焙器的输入是几何。

已准备三个独立空白导航草稿：26000中秋（5列×4行，20张）、26008春节与中秋（各4列×3行，各12张）。窗口顶部可直接切换，首次打开默认选26000中秋。资产保存在 `Assets/MapNavigationDrafts/Festival20261111/`，引用原有44张1024×1024客户端PNG；草稿没有预画通行区域、出生点或烘焙结果。正式世界尺度/有效边界仍待确认，初始300单位宽只是描图工作尺度。

整图共5120×4096或4096×3072像素，缩到小窗口时细节会减少。“1:1 清晰查看”按一个源像素对应一个屏幕像素显示，用中键拖动检查局部；“适合窗口”返回整图。底图分块独立显示，不依赖低清总览图。

## 画一张新地图

1. 点“从整图新建”选择 PNG；或点“从分块新建”，选择包含 `r01_c01.png`、`r01_c02.png` 等的完整矩形目录。行从北到南、列从西到东，必须从 1 开始且不缺块。可用不同尺寸的末行/末列；同列宽度、同行高度须一致。
2. 保存 `.asset` 草稿，推荐 `Assets/MapNavigationDrafts/<地图>/`。项目外底图会按原字节复制到草稿旁的 `Sources`；已在 Assets 内的底图直接引用。随时点顶部“保存当前绘制”，下次把草稿拖入窗口顶部即可继续。此按钮会把正在画、尚未完成的轮廓也加入区域列表并保存全部原始顶点；自交或不足三点的轮廓标记“待修复”，不会静默漏存。
3. 填地图名称、标识、西南角世界原点（X/Z）和世界宽度，高度按原图比例计算。默认的 300 单位仅供开始描绘；使用实际角色和服务端世界比例确认后再勾选“已核实世界范围”。顶点保存为图片像素，调整世界尺寸不会改变描图位置。
4. 选择“圈可走区域”，沿实际可走地面逐点单击，Enter（含小键盘Enter）或双击完成。道路、桥面、平台可分多个区域；相互重叠的可走区会合并。矩形工具可快速圈广场和规则地面。
5. 用“圈障碍区域”或“矩形障碍”围住建筑落地部分、墙、水域等。不同障碍区可以重叠，烘焙时按整体阻挡范围扣除；区域列表仍分别保留原始多边形供编辑。障碍不会生成可走的顶面。同一轮廓内部自交或折返重叠时，Enter会保留全部待绘点并提示冲突边；点“保存当前绘制”或“暂存当前轮廓并调整顶点”可先保存为待修复区域，再修改黄色高亮的冲突边。待修复区域仍禁止烘焙、导出和试走，不会把它当作已完成导航。
6. “调整顶点”可拖点；Shift 单击边线插点，Delete 删除已选点（最少保留 3 点）。左侧区域列表可选择、改名、切换障碍属性或删除区域。编辑支持 Unity 的撤销/重做。中键平移，滚轮以鼠标位置缩放，“适合窗口”复位。
7. 按角色实际占地设置半径、高度、台阶、坡度和体素精度。这些值属于本草稿，不会更改官方全局角色类型配置；离线试走的角色使用草稿同组参数，服务器导出也读取同组参数。图片地图合同显式使用256体素的tile、最小区域面积0，避免沿用全局角色类型或服务器各自的默认值。半径决定角色中心距边缘的退让，窄桥消失时应先检查桥宽和真实半径，不要为通过测试随意缩小角色。
8. 点“烘焙 Unity NavMesh”。绿色半透明填充显示实际烘焙结果；红线为人工障碍轮廓。“试寻路”依次点起终点，只有 `PathComplete` 才画出路线。
9. 用“放出生点”点绿色区域，再点“Play 离线试走”。预览使用这份 NavMesh：左键寻路，WASD 移动，方向键平移相机，滚轮缩放，Home 复位。停止 Play 后恢复原来的编辑场景/启动场景设置。

修改形状、范围、底图身份或角色参数后需要重烘焙；修改名称或出生点不需要。空白新草稿默认没有可走区域。试走与导出会检查出生点是否真的位于当前 NavMesh 上。

烘焙合同已升级为 `authored-flat-v2`，旧版本烘焙数据需要重新烘焙后才能导出。升级不重建或覆盖现有草稿的多边形、出生点和底图引用。

Unity烘焙显式开启高度网格，使地面查询保留源平面Y=0；不会把近似三角网的上浮高度作为新的角色脚点。出生点、编辑器试寻路和Play试走与服务器探针均要求采样结果与原脚点在X/Y/Z每轴相差不超过0.02世界单位，不会随体素变粗扩大吸附容差。自动跳跃和落差连接均明确关闭，避免全局角色类型设置把本来断开的作者区域连起来。

## 修改旧地图

“导入旧标注”可选择含 `layout.png`、`source.json`、`navigation.json` 的旧图目录，例如 `Assets/Resources/World/CurrentMaps20261009/island`（八仙岛）。这会新建可编辑草稿，复制已有可走/障碍多边形作为起点；旧位图的保守采样结果不会被当作新的 NavMesh。旧目录和正式 catalog 不会被这个操作覆盖。

## 给服务端的同源文件

“导出同源几何给服务器”输出：

- `navigation.json`：人工多边形、原图 SHA、原图尺寸、坐标与角色设置，作为可追溯源。
- `world-y-up.obj`：已合并可走区并扣除障碍的三角网，与 Unity 烘焙使用同源几何。OBJ 保持 Unity Y-up、X/Z 地面坐标，无重复换轴。
- `source.json`：几何/标注文件 SHA、作者的范围确认状态；服务端验收状态保持未运行。
- `server-bake-args.json`：服务器 baker 的实际参数字符串数组，包含原始地面出生点 `X,0,Z`；`source.json` 绑定此文件的 SHA-256。配对验证应从导出目录读取此数组调用 baker。
- `server-bake-command.txt`：由同一参数数组生成的人工执行命令参考。

服务端实现位于 `xuanming-server-mmo-cpp/tools/navmesh_baker`，可读 OBJ 并输出其配套 UE5 double ABI 的 Detour MSET v1；**Unity NavMeshData 资产不能直接充当 MSET**。导出使用专供共面 OBJ 的 `--profile authored-flat`，由服务器恢复原始平面高度，不把用户的脚点或出生点抬高。坡度通过 `--agent-slope` 读取草稿值；半径、高度、台阶、水平体素、tile大小与最小区域面积也来自同一合同。普通3D OBJ和已有mask模式不自动采用此共面处理。

服务器 `--ch 0.2` 是服务器侧垂直体素设置；Unity 没有公开对应的cellHeight参数，不能声称垂直精度已完全相同。服务器还会将台阶量化为 `floor(agentClimb / cellHeight)` 个体素；导出元数据记录有效台阶和服务器独有的region合并/悬崖过滤设置。`--min-region-area` 使用世界面积，当前合同为0。相同参数与同源OBJ仍不保证两端生成完全相同的三角网或查询结果，必须比对原脚点、障碍边缘、窄路、断岛及完整路径。若场景还配置了 `nav_mask` 或有效范围约束，也须与新几何同版核对。

2026-11-12 的旧版隔离合成检查曾确认：同一 OBJ 的原始地面为 Unity Y=0，旧服务端 baker 在 `(3,0,6)` 返回 OFF MESH，在诊断点 `(3,0.2,6)` 返回 ON MESH。高度0.2的诊断不能当作原脚点通过。新版合同针对原始共面高度处理这一差异；是否通过以新版客户端/服务器配对验证证据为准，不能用旧截图或旧MSET替代。此次合同改动不修改角色出生高度或服务端正式导航文件。

新版合成验证已通过：隔离Unity源码及实际Play共22项、服务端28项回归，以及同源OBJ生成并重新加载MSET的6组配对例（36个点、6条路径/直线阻挡）；3类旧模式输出与原exe逐字节相同。来源版本、参数、原脚点及吸附容差的红绿证据见`Docs/VerificationEvidence/navmesh-parity-20261112/summary.json`和同目录报告。

两种引擎的轮廓仍不是逐位相同：合成洞边出现过0.1世界单位差别。Unity原始路径拐点/三角网也可保留近似网格Y=0.05，HeightMesh查询及实际角色脚点才是源地面Y=0。每张正式地图仍须检查实际边缘与通路；不能将本次合成测试作为生产地图或联机验收。

此工具保存作者草稿和离线试走资源。正式 catalog 接入、服务端场景登记、边界合同与发布验收使用项目原有交付流程。
