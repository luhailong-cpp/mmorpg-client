## 1. 实际修改了什么

**贴地阴影（新增）** `QdaoBoySpriteAnimator.cs`
程序生成 128px 径向软圆，宽 2.9u，压扁比取地图的 `groundDiscAspect` 0.66，暖褐色峰值 alpha 0.62。只跟脚点走，不随迈腿、朝向、身体起伏变化，排序在人物之下、点击圈之上。

**显示比例** 同文件
`PixelsPerUnit` 64 → 52。只放大人物精灵，相机景别保持 27，底图纹素密度不变。

**待机与跑步衔接** 同文件
拆出 Idle / Run / Settling 三态。停步后不再归零，而是以跑步节奏把动画播到该方向的站立帧再停住，最多一圈约 0.6s。新增方向迟滞 5°、瞬移守卫（速度超 40u/s 判为服务器纠正，不转动画）。

站立帧表 `IdleFrames = {N:2, NE:1, E:1, SE:6, S:2, SW:5, W:2, NW:5}`。W 原本选 6，是双脚分开 17px 的跨步姿势，改成 2。

**点击反馈** `TianyongClickMarker.cs`
改成贴地椭圆：亮青主环 + 深藏青内外镶边 + 中心实心点，160px 带 mipmap。0.7s 生命周期（弹出 → 微扩 → 淡出），同时最多 2 个，锚定世界落点。

**点击不说谎** `TianyongPlayerController.cs`
`ClickAt` 成为鼠标与脚本共用入口，圈落在**实际采纳的路径终点**而非原始点击点。点到屋顶这类不可走位置时，圈出现在最近合法格，人物走到同一个点。

**相机边缘钳制** `TianyongCameraController.cs`
`ClampFocus` 改用**正在渲染**的 `orthographicSize` 而不是目标值。修掉拉远时露出底图边缘的缺陷，同时避免 `max(目标, 渲染)` 写法带来的 105–385px 单帧跳变。跟随参数 SmoothDamp 0.18s 经验证正确，未改。

**名牌** `WorldNameplate.cs`（新增）、`WorldLabelBillboard.cs`、`ActorWorld.cs`、`AppBootstrap.cs`
换成 3D TextMeshPro，SimKai SDF 字体加深色描边，共用一份材质。文字从开发用的 `Player#实体号` 改为会话里的角色名。新增 `LabelSortingBoost = 8000`，让名牌永远画在地面反馈之上。

**右侧三按钮** `BattleUiStyle.cs`、`BattleUiRoot.cs`、`AttributeUiRoot.cs`
战斗、观战、角色统一到一套常量：260×72 设计像素，玉色底板配金色描边，32 号米色字，间距 18，距右缘 40。

**验收台（新增）** `TianyongSandboxAutoDrive.cs`、`TianyongSandboxVerifyBuild.cs`、`tools/run_city_move_verify.ps1`
副本工程离线出包 + 自动走位 + 72 张定点截图。

**遮挡的结论要更正。** 把走路掩码叠回实机画面可以看到，石柱、灯柱、大殿的**整个绘制剪影**都被设成不可走，不只是地面底座。所以人物走不到柱身画到的像素上，也就不会盖住本该遮住它的东西。**不需要前景遮挡切片层。** 代价是可走范围偏保守：走不到灯柱背后，也贴不到柱子底座。要放开就得把掩码收回真实底座，那时才需要切片。

## 5. 过程中修掉的两个方法问题

**离线走位验收会被误按键盘污染。** 播放器窗口抢焦点后，键盘轴优先级高于寻路，会每帧静默清空点击路径，把点击测试变成自由走测试，且不报任何错。新增 `SetScriptedInputOwner` 让脚本独占输入，`Click` 额外打印 `adopted=` 落点。

**待机帧不能按最窄跨度自动挑。** 最窄的往往是抬脚腾空帧。必须在游戏尺寸下目视挑，标准是双脚着地、靠拢、躯干直立。按数值挑 NE_7 时翻过一次车，已改回 NE_1。
